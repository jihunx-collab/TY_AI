# 02. 스킬(Skill) 만들기 — 보고서 양식을 자동화하는 법

## 스킬이 뭔데?

**폴더 하나 + 마크다운 파일 하나.** 그게 다임.

```
.claude/skills/investment-memo/
└── SKILL.md          ← "투자심의보고서 요청이 오면 이렇게 써라"
```

클로드 코드는 이 폴더에서 실행될 때마다 `.claude/skills/` 를 스캔해서,
사용자 요청이 스킬 설명(`description`)과 맞으면 **알아서 그 절차대로** 일함.

### 왜 필요한가 (그냥 프롬프트 붙여넣으면 안 되나)

| 그냥 프롬프트 | 스킬 |
|---|---|
| 매번 양식을 다시 붙여넣어야 함 | `투자심의보고서 써줘` 한 줄 |
| 사람마다 결과물이 다름 | 팀 전원 동일 양식 |
| 양식 바꾸면 전원한테 다시 공지 | 스킬 파일 고치고 push → 끝 |
| 대화 길어지면 앞 지시 잊음 | 필요할 때마다 다시 읽힘 |

---

## 만드는 방법 3가지

### 방법 A. `/skill-creator` 로 대화하며 만들기 ← **처음이면 이거**

```bash
cd ~/TY_AI
claude
```

클로드 안에서:

```
> /skill-creator
```

그러면 클로드가 인터뷰를 시작함. 답만 하면 됨:

```
클로드: 어떤 스킬을 만들까요?
나:     투자심의보고서 작성 스킬. VC 투심위에 올리는 문서야.

클로드: 어떤 요청일 때 이 스킬이 발동해야 하나요?
나:     "투심보고서", "투자심의보고서", "IC 메모", "딜 검토 보고서" 같은 말이 나올 때

클로드: 결과물의 형식과 필수 항목은요?
나:     마크다운. 목차는 딜 개요 / 회사개요 / 시장 / 재무 / 밸류에이션 /
        투자포인트 / 리스크 / Exit전략 / 투자조건 / 심의요청사항.
        숫자는 반드시 출처 표기하고, 추정치는 [추정] 붙여야 함.

클로드: 참고할 기존 보고서 샘플이 있나요?
나:     reports/샘플/ 폴더에 2개 있어. 그거 톤 참고해줘.
```

→ 클로드가 `.claude/skills/투자심의보고서/SKILL.md` 를 만들어 줌.
→ 바로 테스트하고 고치면 됨.

> **팁**: 기존에 잘 쓴 보고서 파일이 있으면 그걸 클로드한테 읽히는 게 제일 빠름.
> `이 보고서 3개 읽고 공통 양식 뽑아서 스킬로 만들어줘 @reports/A.md @reports/B.md`

### 방법 B. 파일 직접 만들기

```bash
mkdir -p .claude/skills/내스킬이름
```

`.claude/skills/내스킬이름/SKILL.md`:

```markdown
---
name: 내스킬이름
description: 언제 이 스킬을 써야 하는지 한 문장. 여기에 발동 키워드를 다 넣을 것.
---

# 스킬 제목

## 언제 쓰나
...

## 작업 절차
1. ...
2. ...

## 산출물 양식
...

## 규칙
- 하지 말아야 할 것
```

**핵심은 `description`.** 클로드가 이 한 줄만 보고 "이 스킬 쓸까 말까"를 결정함.
→ 사용자가 실제로 칠 법한 말을 최대한 많이 박아넣기.

```yaml
# 나쁨
description: 투자 보고서를 만듭니다.

# 좋음
description: 투자심의보고서/투심보고서/IC메모/딜검토보고서 작성 및 검토 시 사용.
  "투심 올려야 해", "○○사 투자 검토 문서", "심의자료 만들어줘" 같은 요청 포함.
  스타트업·비상장사 지분투자 건의 목차, 밸류에이션, 리스크, Exit 시나리오 정리에 사용.
```

### 방법 C. 이미 있는 스킬 복사해서 고치기

이 레포의 `investment-memo` 스킬을 복사해서 다른 보고서용으로 바꾸는 게 제일 빠름:

```bash
cp -r .claude/skills/investment-memo .claude/skills/사후관리보고서
# SKILL.md 열어서 name / description / 목차만 바꾸기
```

---

## 스킬 폴더 구조 (파일 여러 개 쓸 때)

SKILL.md 가 길어지면 쪼갬. 클로드가 **필요할 때만** 참조 파일을 읽어서 효율적임.

```
.claude/skills/investment-memo/
├── SKILL.md                      ← 절차 (항상 읽힘, 짧게 유지)
├── references/
│   ├── report-template.md        ← 보고서 목차 원본
│   ├── valuation-guide.md        ← 밸류에이션 방법론
│   └── risk-checklist.md         ← 리스크 점검 항목
└── assets/
    └── 투심보고서_양식.docx        ← 회사 공식 워드 양식
```

SKILL.md 안에서 이렇게 가리킴:

```markdown
목차는 `references/report-template.md` 를 그대로 따를 것.
밸류에이션 산정 시 `references/valuation-guide.md` 를 먼저 읽을 것.
```

## 스킬 두는 위치

| 위치 | 범위 | 언제 |
|---|---|---|
| `프로젝트/.claude/skills/` | 이 레포에서만 | **팀 공용.** git 으로 공유됨 ← 기본값 |
| `~/.claude/skills/` | 내 맥 전체 | 개인용, 어느 폴더에서든 |

**팀 스킬은 반드시 레포 안(`TY_AI/.claude/skills/`)에.** 그래야 push/pull 로 공유됨.

---

## 만들고 나서: 테스트 → 수정 루프

1. `claude` 실행
2. `/context` 로 스킬이 로드됐는지 확인 (또는 그냥 `무슨 스킬 있어?` 라고 물어보기)
3. 실제 요청을 던져봄 — **스킬 이름을 말하지 말고** 평소 말투로:
   ```
   > ○○테크 시리즈A 30억 투자 건 심의보고서 초안 잡아줘
   ```
4. 스킬이 안 걸리면 → `description` 에 그 말투를 추가
5. 결과물이 마음에 안 들면 → 그 자리에서 클로드한테 말하기:
   ```
   > 지금 나온 결과에서 Exit 시나리오 부분이 너무 얕아.
     IRR/MOIC 3개 시나리오(Base/Bull/Bear) 표로 강제하도록 스킬 고쳐줘
   ```
   클로드가 SKILL.md 를 직접 수정해 줌.
6. 만족하면 커밋:
   ```bash
   git add .claude/skills && git commit -m "투심 스킬 Exit 시나리오 보강" && git push
   ```

## 금융 보고서 스킬 만들 때 꼭 넣을 것

숫자가 틀리면 사고임. 스킬에 **강제 규칙**으로 박아둘 것:

```markdown
## 절대 규칙
- 출처 없는 숫자를 쓰지 말 것. 모르면 `[확인필요]` 로 남길 것.
- 실적치와 추정치를 구분: 실적은 `[실적]`, 회사제시 추정은 `[회사추정]`, 자체추정은 `[자체추정]`
- 재무 수치는 단위(백만원/억원)와 기준일(FY24, '25.1H)을 항상 병기
- 회사가 준 자료 원문에 없는 수치를 임의로 만들지 말 것
- 계산이 들어가면 계산식을 각주로 남길 것 (밸류, 지분율, IRR 등)
- 최종본은 사람이 검토하기 전까지 "초안"으로 표기
```

이게 없으면 그럴듯한 가짜 숫자가 섞임. **이건 반드시 넣어라.**

## 다음 단계로 만들면 좋은 스킬들

| 스킬 | 하는 일 |
|---|---|
| `investment-memo` | 투자심의보고서 ← 이 레포에 이미 있음 |
| `deal-screening` | IR덱/사업계획서 받아서 1차 스크리닝 메모 |
| `financial-model-review` | 엑셀 재무모델 뜯어서 가정 검증 |
| `portfolio-update` | 분기 사후관리 보고서 |
| `market-research` | 시장규모/경쟁사 리서치 정리 |
| `term-sheet-review` | 텀시트 조항 체크리스트 대조 |

만드는 순서 추천: **가장 자주 쓰는 것 1개부터.** 여러 개 한꺼번에 만들면 다 어중간해짐.
