# 1. 스킬이 뭔데?

**폴더 하나 + 마크다운 파일 하나.** 그게 전부입니다.

```
.claude/skills/투자심의보고서/
└── SKILL.md          ← "투자심의보고서 요청이 오면 이렇게 써라"
```

클로드 코드는 이 폴더에서 실행될 때마다 `.claude/skills/` 를 훑어봅니다.
그리고 내가 한 요청이 스킬 설명과 맞으면 **알아서 그 절차대로** 일합니다.

## 왜 필요한가 — 그냥 프롬프트 붙여넣으면 안 되나?

| 매번 프롬프트 붙여넣기 | 스킬로 만들어두기 |
|---|---|
| 양식을 매번 다시 붙여넣어야 함 | `투심보고서 초안 잡아줘` 한 줄 |
| 사람마다 결과물이 제각각 | 팀 전원이 동일한 양식 |
| 양식 바꾸면 전원에게 다시 공지 | 파일 하나 고쳐서 push → 끝 |
| 대화가 길어지면 앞의 지시를 잊음 | 필요할 때마다 다시 읽힘 |
| 잘 쓴 프롬프트가 대화창과 함께 사라짐 | 파일로 남아 계속 개선됨 |

## 한 줄 요약

> **"이번에 잘 나온 결과"를 다음에도 나오게 만드는 장치.**

# 2. 만들기 전에 — 재료 준비

⚠️ **백지에서 시작하지 마세요.** 스킬 품질은 재료 품질이 결정합니다.

## 있으면 좋은 재료 (하나만 있어도 됨)

| 재료 | 왜 |
|---|---|
| **잘 쓴 기존 보고서 2~3개** | 제일 강력합니다. 목차·톤·디테일 수준이 통째로 복제됨 |
| 회사 공식 양식 (docx/hwp) | 목차를 그대로 강제할 수 있음 |
| 심의에서 지적받았던 내용 | "이건 꼭 넣어라" 규칙의 재료 |
| 반대로 못 쓴 보고서 | "이렇게 하지 마라" 규칙의 재료 |

## 재료를 레포에 넣기

```bash
cd ~/TY_AI
mkdir -p reports/샘플
```

이 폴더에 기존 보고서 파일을 복사해 넣으세요.
Finder에서 드래그해도 되고, 터미널이 편하면:

```bash
cp ~/Downloads/A사_투자심의보고서.docx reports/샘플/
```

> ⚠️ `.docx` `.pdf` `.xlsx` 는 실수로 업로드되지 않게 `.gitignore` 로 막혀 있습니다.
> 내 맥에서만 클로드가 읽고, GitHub에는 안 올라갑니다. 안심하고 넣으세요.

# 3. 만드는 법 ① `/skill-creator` 로 대화하며 (처음이면 이것)

```bash
cd ~/TY_AI
claude
```

클로드가 뜨면:

```
> /skill-creator
```

그러면 클로드가 **인터뷰**를 시작합니다. 질문에 답만 하면 됩니다.

## 실제 대화 예시 (이대로 따라 해도 됩니다)

```
🤖 어떤 스킬을 만들까요? 목적과 용도를 알려주세요.

👤 투자심의보고서 작성 스킬. VC 투자심의위원회에 올리는 문서야.
   내가 딜 자료를 주면 표준 목차대로 초안을 잡아주면 돼.

🤖 어떤 요청이 들어왔을 때 이 스킬이 발동해야 하나요?
   실제로 쓰실 법한 표현을 최대한 많이 알려주세요.

👤 "투심보고서", "투자심의보고서", "심의자료", "IC 메모", "딜 검토 문서",
   "○○사 투자 건 정리해줘", "이 딜 투심에 올려야 해" 이런 말들.

🤖 결과물의 형식과 필수 목차를 알려주세요.

👤 마크다운으로. 목차는 이 순서 고정이야:
   딜 개요 → 요약 → 회사 개요 → 사업/제품 → 시장 분석 → 재무 분석
   → 밸류에이션 → 투자 포인트 → 리스크 → Exit 전략 → 투자 조건 → 심의 요청사항

🤖 반드시 지켜야 할 규칙이나, 절대 하면 안 되는 것이 있나요?

👤 숫자가 제일 중요해. 세 가지 꼭 지켜줘:
   1. 출처 없는 숫자 쓰지 마. 모르면 [확인필요]로 비워둘 것
   2. 실적/추정을 반드시 구분해서 [실적] [회사추정] [자체추정] 라벨 붙일 것
   3. 계산이 들어간 값(지분율, IRR, 밸류 배수)은 계산식을 각주로 남길 것
   그리고 리스크 섹션을 형식적으로 두 줄 쓰고 넘어가지 마. 최소 3개, 각각 대응방안까지.

🤖 참고할 기존 보고서가 있나요?

👤 응, reports/샘플/ 폴더에 3개 있어. 그거 읽고 목차랑 톤 맞춰줘.

🤖 결과물은 어디에 저장할까요?

👤 reports/회사명/투자심의보고서_초안_날짜.md 로.

🤖 정리했습니다. 아래 내용으로 만들까요?
   [초안 보여줌]

👤 좋아. 만들어줘.
```

**▶ 이렇게 나오면 성공**
```
✓ Created .claude/skills/투자심의보고서/SKILL.md
✓ Created .claude/skills/투자심의보고서/references/report-template.md
```

바로 [6번 — 테스트](#6-테스트하고-고치기-제일-중요) 로 가세요.

## 🔥 더 빠른 방법 — 기존 보고서를 그냥 던지기

`/skill-creator` 를 쓰지 않고 이렇게만 해도 됩니다. 사실 이게 제일 좋습니다.

```
> reports/샘플/ 폴더에 있는 투심보고서 3개를 읽어줘.
  공통 목차, 서술 톤, 숫자 표기 방식을 뽑아서
  "투자심의보고서" 라는 이름의 스킬로 만들어줘.
  다음부터는 내가 딜 자료만 주면 같은 양식으로 초안이 나오게.
```

클로드가 파일을 읽고 → 공통점을 분석하고 → SKILL.md 를 만들어 줍니다.
**내 회사 양식이 그대로 반영되기 때문에 처음부터 설명하는 것보다 훨씬 정확합니다.**

# 4. 만드는 법 ② 파일 직접 쓰기

구조를 이해하고 싶거나, 이미 머릿속에 양식이 있으면 직접 만들어도 됩니다.

```bash
mkdir -p .claude/skills/투자심의보고서
```

그리고 `.claude/skills/투자심의보고서/SKILL.md` 파일을 만들어 아래 형식으로 씁니다.
(VS Code에서 열거나, 터미널에서 `code .claude/skills/투자심의보고서/SKILL.md`)

```markdown
---
name: 투자심의보고서
description: 언제 이 스킬을 써야 하는지 한 문장. 발동 키워드를 여기에 전부 넣을 것.
---

# 투자심의보고서 작성

## 절차
1. 사용자가 준 자료를 전부 읽는다
2. 자료가 부족한 항목을 먼저 목록으로 보여준다
3. 아래 양식대로 작성한다
4. 스스로 검수한다

## 산출물 양식
(목차를 여기에)

## 절대 규칙
- 출처 없는 숫자를 쓰지 않는다
- ...

## 하지 말 것
- ...
```

## ⭐ 핵심은 `description` 한 줄입니다

클로드는 이 한 줄만 보고 **"이 스킬을 쓸까 말까"** 를 결정합니다.
→ 내가 실제로 칠 법한 말을 최대한 많이 넣으세요.

```yaml
# ❌ 나쁨 — 이러면 스킬이 발동을 안 합니다
description: 투자 보고서를 만듭니다.
```

```yaml
# ✅ 좋음 — 실제 말투가 다 들어있음
description: 투자심의보고서·투심보고서·IC메모·딜검토보고서·심의자료 작성 및 검토 시 사용.
  "투심 올려야 해", "○○사 투자 검토 문서 만들어줘", "심의자료 초안",
  "이 딜 IC에 올릴 자료" 같은 요청에 발동.
  스타트업·비상장사 지분투자(시리즈A~C, RCPS, CB) 건의 목차·밸류에이션·
  리스크·Exit 시나리오 정리에 사용. 기존 투심보고서 리뷰·보완 요청에도 사용.
```

> **팁:** 스킬이 자꾸 발동을 안 하면, 십중팔구 `description` 문제입니다.
> 내가 방금 친 말을 그대로 description 에 추가하면 해결됩니다.

# 5. 만드는 법 ③ 기존 스킬 복사

스킬이 하나라도 생기면, 그 다음부터는 복사가 제일 빠릅니다.

```bash
cp -r .claude/skills/투자심의보고서 .claude/skills/사후관리보고서
```

그리고 새로 생긴 `SKILL.md` 를 열어서 **`name`, `description`, 목차** 세 군데만 고치면 됩니다.

클로드한테 시켜도 됩니다:

```
> 투자심의보고서 스킬을 복사해서 "분기 사후관리보고서" 스킬을 만들어줘.
  투자 검토용이 아니라 이미 투자한 회사의 분기 실적을 추적하는 문서야.
  밸류에이션이랑 투자조건 섹션은 빼고, 대신 KPI 추이랑 마일스톤 달성률을 넣어줘.
```

# 6. 테스트하고 고치기 (제일 중요)

**스킬은 한 번에 완성되지 않습니다.** 3~4번 돌려보고 고치는 게 정상입니다.

## ① 스킬이 인식됐는지 확인

클로드 안에서:

```
> 지금 쓸 수 있는 스킬 목록 보여줘
```

**▶ 이렇게 나오면 성공**
```
현재 이 프로젝트에서 사용 가능한 스킬:
- 투자심의보고서: 투자심의보고서·투심보고서·IC메모 작성 및 검토 시 사용...
```

**▶ 목록에 없으면**
- 파일 위치가 맞나요? → `.claude/skills/이름/SKILL.md` (파일명은 대문자 `SKILL.md`)
- 클로드를 껐다 켜보세요 (`/exit` → `claude`)
- 맨 위 `---` 로 감싼 `name:` / `description:` 이 빠지지 않았나요?

## ② 실제로 돌려보기 — ⚠️ 스킬 이름을 말하지 마세요

```
> ❌ 투자심의보고서 스킬로 초안 만들어줘
```
이건 테스트가 안 됩니다. 스킬 이름을 부르면 당연히 발동하니까요.

```
> ✅ ○○테크 시리즈A 30억 투자 건, 심의보고서 초안 좀 잡아줘
```

**평소에 쓸 말투로** 요청해야 진짜 테스트입니다.
스킬이 발동하면 클로드가 이렇게 알려줍니다:

```
투자심의보고서 스킬을 사용해 초안을 작성하겠습니다.
먼저 자료를 확인하겠습니다...
```

## ③ 마음에 안 드는 부분을 그 자리에서 고치기

**파일을 직접 열 필요 없습니다.** 클로드한테 말하면 스킬 파일을 알아서 수정합니다.

```
> Exit 시나리오 부분이 너무 얕아. Base/Bull/Bear 3개 시나리오를
  MOIC랑 IRR까지 포함한 표로 반드시 넣게 스킬을 고쳐줘.
```

```
> 리스크 섹션에 "발생 가능성 / 영향도 / 대응방안" 3개 컬럼 표를 강제해줘.
  최소 3개 이상 안 쓰면 안 되게.
```

```
> 지금 나온 초안에서 숫자에 출처가 안 붙은 게 있어.
  스킬의 절대 규칙을 더 강하게 써서 이런 게 안 나오게 해줘.
```

```
> 매번 "초안" 이라고 표기하는 걸 자꾸 빼먹네. 파일명이랑 문서 맨 위에
  무조건 "초안" 이 들어가게 규칙 추가해줘.
```

## ④ 다시 ②로 — 만족할 때까지 반복

보통 **3~4번 반복하면 쓸 만해집니다.**

# 7. 팀에 공유하기

스킬이 마음에 들면 GitHub에 올립니다. 그러면 팀원 전체가 같은 스킬을 씁니다.

## 클로드한테 시키는 방법 (쉬움)

```
> 방금 만든 스킬 커밋해서 push 해줘
```

## 직접 하는 방법

```bash
git add .claude/skills
git commit -m "투자심의보고서 스킬 추가"
git push
```

**▶ 이렇게 나오면 성공**
```
[main a1b2c3d] 투자심의보고서 스킬 추가
 2 files changed, 87 insertions(+)
To https://github.com/jihunx-collab/TY_AI.git
   1234567..a1b2c3d  main -> main
```

## 팀원이 받는 방법

```bash
cd ~/TY_AI
git pull
```

끝입니다. 다음에 `claude` 를 켜면 그 스킬이 바로 잡힙니다.

> **작업 시작 전엔 항상 `git pull`** 하는 습관을 들이면 좋습니다.
> 남이 개선한 스킬을 놓치지 않습니다.

# 8. 금융 보고서 스킬에 꼭 넣을 것

숫자가 틀리면 사고입니다. 아래를 **그대로 복사해서** SKILL.md 에 붙여넣으세요.

```markdown
## 절대 규칙 (금융 문서)

- **출처 없는 숫자를 쓰지 않는다.** 모르면 `[확인필요]` 로 비워둔다.
- **모든 수치에 라벨을 붙인다**: `[실적]` / `[회사추정]` / `[자체추정]` / `[2차자료]`
- **모든 재무 수치에 단위와 기준을 병기한다**
  예: `매출 128억원 [실적, FY24, 별도기준]`
- 자료 원문에 없는 수치를 만들어내지 않는다. 보간·유추도 하지 않는다.
- 계산이 들어간 값(투자단가, 지분율, IRR, MOIC, 배수)은 **계산식을 각주로 남긴다.**
- 시장 규모(TAM/SAM/SOM)는 출처 기관명과 발행연도를 반드시 적는다. 없으면 쓰지 않는다.
- 회사 IR 자료의 주장과 검증된 사실을 분리해서 쓴다.
  ("회사에 따르면 ~" vs "재무제표상 ~")
- 파일명과 문서 상단에 **"초안"** 표기를 유지한다. 사람이 검토 후 직접 뗀다.
- 투자 찬반 결론을 임의로 단정하지 않는다. 판단 근거를 제시하고 결론은 심의에 맡긴다.
```

**이게 없으면 그럴듯한 가짜 숫자가 섞입니다. 반드시 넣으세요.**

## 그리고 산출물을 받으면 꼭 확인할 것

| 확인 | 왜 |
|---|---|
| `[확인필요]` 가 몇 개 남았나 | 이게 0개인데 자료가 부족했다면 → 숫자를 지어낸 것 |
| 계산식 각주가 재현되나 | 직접 계산기로 한 번 두들겨보기 |
| 회사 주장과 검증 사실이 섞였나 | 제일 위험한 부분 |
| 리스크가 형식적이지 않나 | 심의에서 제일 먼저 깨지는 곳 |

> 🚨 **AI가 만든 건 언제나 "초안"입니다.** 숫자는 사람이 검증한 뒤에 제출하세요.

# 9. 스킬 폴더 구조 (길어졌을 때)

SKILL.md 가 200줄을 넘어가면 쪼갭니다.
클로드가 **필요할 때만** 참조 파일을 읽기 때문에 더 효율적입니다.

```
.claude/skills/투자심의보고서/
├── SKILL.md                      ← 절차와 규칙 (항상 읽힘. 짧게 유지)
├── references/                   ← 필요할 때만 읽힘
│   ├── report-template.md        ← 보고서 목차 원본
│   ├── valuation-guide.md        ← 밸류에이션 방법론
│   └── risk-checklist.md         ← 리스크 점검 항목
└── assets/
    └── 투심보고서_양식.docx        ← 회사 공식 워드 양식
```

SKILL.md 안에서 이렇게 가리킵니다:

```markdown
목차는 `references/report-template.md` 를 그대로 따를 것.
밸류에이션 산정 시 `references/valuation-guide.md` 를 먼저 읽을 것.
리스크 작성 전 `references/risk-checklist.md` 를 전부 점검할 것.
```

## 스킬을 어디에 둘까

# 10. 자주 하는 실수

| 실수 | 증상 | 해결 |
|---|---|---|
| `description` 이 너무 짧음 | 스킬이 발동을 안 함 | 실제 말투를 전부 넣기 ([4번](#-핵심은-description-한-줄입니다)) |
| 파일명이 `skill.md` (소문자) | 인식 안 됨 | **`SKILL.md`** 대문자로 |
| 맨 위 `---` 블록 누락 | 인식 안 됨 | `name:` / `description:` 을 `---` 로 감싸기 |
| 한 번에 스킬 5개 만들기 | 전부 어중간함 | **제일 자주 쓰는 것 1개부터.** 완성한 뒤 다음 것 |
| 백지에서 스킬 작성 | 남의 양식이 나옴 | 기존 보고서를 먼저 읽히기 ([2번](#2-만들기-전에--재료-준비)) |
| 스킬 이름을 부르며 테스트 | 개선점이 안 보임 | 평소 말투로 요청 ([6번 ②](#-실제로-돌려보기--️-스킬-이름을-말하지-마세요)) |
| 만들고 push 안 함 | 나만 쓰게 됨 | `> 커밋하고 push 해줘` |
| 대화가 계속 길어짐 | 답변 품질 저하 | 보고서 하나 끝날 때마다 `/clear` |
